# Security Testing

<TagList tags={frontmatter.tags} />
<AttributionList contributors={frontmatter.contributors} />

Security testing in DevSecOps should combine multiple methods across the delivery lifecycle. No single scanner catches
every class of issue.

## Recommended controls

1. Run SAST on every pull request for early developer feedback.
2. Run DAST against deployed preview/staging environments.
3. Add dependency and container-image vulnerability scanning.
4. Use fuzz testing for parsers, protocol handling, and custom business logic.
5. Track findings to remediation SLAs by severity.

## Practical examples

### Example 1: PR-level SAST gate

Run static analysis in CI and block merges on high-confidence findings in critical paths.

### Example 2: DAST against preview environments

For web apps, execute authenticated ZAP/Burp-style scans against preview deployments created per pull request.

### Example 3: Targeted fuzzing for high-risk components

Use fuzzing harnesses for ABI parsers, transaction decoders, serialization logic, and signing flows.

### Example 4: Risk-based triage workflow

Route findings to owners by subsystem and enforce response windows (for example: critical within 24h, high within 7d).
