# Integrated Development Environments (IDEs)

<TagList tags={frontmatter.tags} />
<AttributionList contributors={frontmatter.contributors} />

IDEs are often trusted with source code, credentials, and cloud access. Treat development environments as part of your
security boundary.

## Recommended controls

1. Install extensions only from trusted publishers and maintain an internal allowlist.
2. Keep IDEs/extensions updated and remove abandoned plugins.
3. Enable restricted/workspace trust mode for untrusted repositories.
4. Enforce least privilege for local credentials, shells, and integrated terminals.
5. Isolate development from production with separate accounts, networks, and credentials.

## Practical examples

### Example 1: Use VS Code Workspace Trust for untrusted code

When opening unknown repos, keep **Restricted Mode** enabled until files and extensions are reviewed.

### Example 2: Standardize secure local setups with Dev Containers

Define a hardened `.devcontainer` so developers use the same baseline tooling, linters, and security checks.
This reduces drift and limits risky host-level customization.

### Example 3: Catch secrets before commit

Run secret scanning locally (for example, `gitleaks` or `trufflehog`) as a pre-commit/pre-push hook so credentials are
blocked before they reach CI.

### Example 4: Separate developer and production identities

Use non-production cloud accounts for daily development and require privileged access workflows (break-glass + approval)
for production actions.
