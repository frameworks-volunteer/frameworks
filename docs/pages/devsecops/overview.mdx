# DevSecOps

<TagList tags={frontmatter.tags} />
<AttributionList contributors={frontmatter.contributors} />

Traditionally, rapid development and deployment is often prioritized at the expense of security considerations. This is
generally speaking no different in web3, but it is important to take integrity, confidentiality, and availability into
consideration too. To effectively address this without compromising on rapid development and deployment, it is essential
to integrate security into the process, which is where devsecops comes into play. By implementing devsecops, projects
can not only deploy faster, but also be more secure.

When operating in a devsecops mindset, projects prioritizes automation and collaboration between the development,
operations and security teams.

Some of the key areas to consider are:

1. Integrate security controls early in the development process (for example SAST, dependency scanning, and reproducible
  builds).
2. Implement automated security testing and monitoring across CI/CD.
3. Align Development, Operations, and Security teams around shared ownership and response playbooks.

## DevSecOps subsections

- [Repository Hardening](/devsecops/repository-hardening): branch/ruleset protections, secret scanning, and access
  governance.
- [Code Signing](/devsecops/code-signing): commit/tag verification and artifact provenance.
- [Integrated Development Environments](/devsecops/integrated-development-environments): secure local environments,
  extension trust, and credential isolation.
- [Continuous Integration and Continuous Deployment](/devsecops/continuous-integration-continuous-deployment):
  least-privilege workflows, pinned actions, and OIDC federation.
- [Security Testing](/devsecops/security-testing): SAST/DAST/IAST, fuzzing, and remediation pipelines.
