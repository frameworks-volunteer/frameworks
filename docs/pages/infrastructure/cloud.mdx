# Cloud Infrastructure

<TagList tags={frontmatter.tags} />
<AttributionList contributors={frontmatter.contributors} />

For many teams, your cloud footprint is effectively part of your protocol perimeter. Even if contracts are secure,
compromised CI, RPC, DNS, frontend hosting, or cloud IAM can still lead to major losses.

## Baseline Security Controls

At minimum, implement:

1. **Strong identity controls**: SSO + MFA for all operators, role-based access control (RBAC), and just-in-time access
   for privileged actions.
2. **Data protection**: Encrypt data in transit and at rest. Prefer managed KMS/HSM backed keys and strict key rotation
   procedures.
3. **Network segmentation**: Keep critical services in private subnets/VNETs, restrict ingress to approved sources, and
   avoid public management interfaces.
4. **Tamper-evident logging**: Enable cloud audit logs for all regions/accounts/projects and centralize retention.
5. **Detection + alerting**: Configure real-time alerts for IAM changes, key usage anomalies, public bucket exposure,
   and suspicious API activity.
6. **Resilience planning**: Multi-zone architecture, regular backups, tested restore plans, and clear RTO/RPO targets.
7. **Compliance posture**: Map controls to your obligations (e.g., GDPR, SOC2, MiCA requirements where applicable).

## Provider-Specific Hardening Starters

### AWS

- Use **AWS Organizations** with separate accounts for production, staging, security, and shared services.
- Enforce global guardrails through **Service Control Policies (SCPs)**.
- Use **AWS IAM Identity Center** and avoid long-lived IAM users whenever possible.
- Keep workloads in private subnets and gate ingress with **Security Groups + NACLs + WAF** where appropriate.
- Enable **CloudTrail**, **Config**, **GuardDuty**, and **Security Hub** organization-wide.
- Protect sensitive workloads with **KMS**, and monitor key usage via CloudWatch/EventBridge alerts.

### Azure

- Structure access with **Management Groups → Subscriptions → Resource Groups**.
- Use **Microsoft Entra ID** with conditional access and **Privileged Identity Management (PIM)**.
- Isolate services using **VNets**, **NSGs**, **Private Endpoints**, and deny broad public ingress by default.
- Enable **Defender for Cloud**, **Azure Monitor**, and **Activity Logs** for security telemetry.
- Apply **Azure Policy** to enforce approved regions, SKUs, and encryption requirements.

### GCP

- Use **Organization → Folders → Projects** to isolate environments and blast radius.
- Apply least privilege with IAM and avoid static service-account keys (prefer workload identity federation).
- Protect sensitive APIs/services with **VPC Service Controls** and private networking.
- Enable **Cloud Audit Logs**, **Security Command Center**, and centralized alerting.
- Use **Cloud Armor** for internet-exposed workloads and explicit ingress restrictions.

## Ethereum Node Deployment Examples (AWS, Azure, GCP)

A secure production pattern for ETH nodes is usually:

- Execution client + consensus client on hardened hosts
- Private networking by default
- Restricted RPC exposure (allowlist, auth, rate limits)
- Full metrics/logging and alerting
- Automated backup + tested recovery

### AWS example pattern

- **Compute**: EC2 (or EKS for containerized nodes)
- **Storage**: GP3/EBS volumes sized for execution + consensus data growth
- **Network**: private subnets, tightly scoped security groups
- **Access**: SSM Session Manager instead of open SSH
- **Observability**: CloudWatch + Prometheus/Grafana

Practical checks:

- RPC (8545/8546) not open to the public internet
- P2P ports are only as open as required
- Systemd hardening for node processes
- Snapshot/backup cadence documented and tested

### Azure example pattern

- **Compute**: Azure VM Scale Set or AKS
- **Storage**: Managed Disks sized for chain growth and IO requirements
- **Network**: private VNET, NSG rules scoped to known peers/clients
- **Access**: Azure Bastion / JIT VM access via Defender
- **Observability**: Azure Monitor + Prometheus/Grafana

Practical checks:

- Management ports restricted to approved admin paths only
- Defender alerts configured for unusual process/network behavior
- Key material (JWT secret, API creds) in Key Vault

### GCP example pattern

- **Compute**: Compute Engine managed instance groups or GKE
- **Storage**: Persistent Disks with tuned performance profiles
- **Network**: private VPC, minimal firewall exposure
- **Access**: IAP + OS Login + MFA for operators
- **Observability**: Cloud Logging/Monitoring + Prometheus/Grafana

Practical checks:

- No unauthenticated public RPC endpoints
- Alerting for sync lag, peer drops, and disk pressure
- Service account permissions are minimal and reviewed periodically
